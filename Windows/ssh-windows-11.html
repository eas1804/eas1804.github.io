Установка SSH-сервера

Краткая инструкция для удалённого доступа к компьютеру Windows 11 через встроенный OpenSSH Server.

1. Установить OpenSSH Server

На удалённом компьютере откройте PowerShell от имени администратора. Проверьте компонент и при необходимости установите его:

Get-WindowsCapability -Online -Name OpenSSH.Server*
Add-WindowsCapability -Online -Name OpenSSH.Server~~~~0.0.1.0

После установки состояние компонента должно быть Installed. Установка может потребовать доступа к Windows Update.

2. Ограничить входящие подключения

Установка OpenSSH может создать разрешающее правило Windows Firewall для TCP/22. До запуска службы ограничьте его разрешёнными IP-адресами. В примере указаны два учебных адреса: замените их фактическими адресами клиентов. Для VPN или локальной сети укажите адрес клиента или его подсеть.

$sshAllowedIPs = @(
    '192.0.2.10', '198.51.100.20'
)

$sshRule = Get-NetFirewallRule -Name 'OpenSSH-Server-In-TCP' -ErrorAction SilentlyContinue
if ($sshRule) {
    $sshRule | Set-NetFirewallRule -Enabled True -RemoteAddress $sshAllowedIPs
} else {
    New-NetFirewallRule -Name 'OpenSSH-Server-In-TCP' `
        -DisplayName 'OpenSSH Server (sshd)' -Enabled True `
        -Direction Inbound -Protocol TCP -Action Allow -LocalPort 22 `
        -RemoteAddress $sshAllowedIPs
}

Проверьте остальные правила: другое включённое разрешающее правило для TCP/22 может разрешить подключения за пределами этого списка. Ограничение одного правила не отменяет другие разрешения. При подключении по IPv6 необходимо настроить отдельные разрешённые IPv6-адреса или убедиться, что другие правила не открывают порт по IPv6.

Get-NetFirewallRule -Enabled True -Direction Inbound -Action Allow |
    Where-Object { ($_ | Get-NetFirewallPortFilter).LocalPort -in @('22', 'Any') } |
    Select-Object DisplayName, Name, Profile

Команда показывает кандидатов для проверки, включая широкие правила. Учитывайте также правила, ограниченные программой или службой, и политику домена.

3. Запустить службу

Set-Service -Name sshd -StartupType Automatic
Start-Service sshd
Get-Service sshd
Get-NetTCPConnection -State Listen -LocalPort 22

Служба должна иметь статус Running, а порт 22 — находиться в состоянии прослушивания. Существующую RDP-сессию оставьте открытой до успешной проверки SSH.

4. Проверить подключение

На Windows 11 узнайте имя пользователя и адрес интерфейса:

whoami
ipconfig

С другого компьютера проверьте доступность порта и подключитесь:

Test-NetConnection -ComputerName <IP-или-DNS> -Port 22
ssh <пользователь>@<IP-или-DNS>

При первом подключении сверьте отпечаток ключа сервера по доверенному каналу. При необходимости на сервере его можно вывести так:

ssh-keygen -lf C:\ProgramData\ssh\ssh_host_ed25519_key.pub

Если сервер за NAT, для подключения извне нужен маршрут к нему: например, VPN либо соответствующая настройка маршрутизатора и внешнего firewall. Открытый порт Windows Firewall сам по себе не создаёт такой маршрут.

5. Настроить вход по ключу

На клиентском компьютере создайте отдельную пару ключей Ed25519:

ssh-keygen -t ed25519

Укажите путь для сохранения или нажмите Enter, чтобы принять путь по умолчанию. При необходимости задайте парольную фразу. Закрытый ключ остаётся на клиенте; на сервер передаётся только содержимое файла с расширением .pub.

Например, в PowerShell покажите открытый ключ по пути по умолчанию:

Get-Content "$env:USERPROFILE\.ssh\id_ed25519.pub"

Для обычного пользователя Windows добавьте содержимое открытого ключа в файл %USERPROFILE%\.ssh\authorized_keys этого пользователя. Для учётной записи, входящей в группу администраторов, стандартная конфигурация Windows использует общий файл C:\ProgramData\ssh\administrators_authorized_keys.

Для административной учётной записи на сервере откройте PowerShell от имени администратора и добавьте свой открытый ключ:

$publicKey = 'ВСТАВЬТЕ_СОДЕРЖИМОЕ_ФАЙЛА_PUB'
$keyFile = 'C:\ProgramData\ssh\administrators_authorized_keys'
Add-Content -LiteralPath $keyFile -Value $publicKey -Encoding UTF8
icacls.exe $keyFile /inheritance:r /grant:r '*S-1-5-32-544:F' '*S-1-5-18:F'
icacls.exe $keyFile

Add-Content добавляет ключ к существующим. Убедитесь, что ACL файла содержит разрешения только для группы администраторов и SYSTEM: команда не удаляет ранее заданные явные разрешения других учётных записей. Подробности настройки ключей и ACL приведены в документации Microsoft.

Подключитесь с клиентского компьютера, указав закрытый ключ, если он сохранён не по стандартному пути:

ssh -i <путь_к_закрытому_ключу> <пользователь>@<IP-или-DNS>

До отключения парольной аутентификации проверьте вход по ключу в отдельной сессии и сохраните доступ по RDP.
